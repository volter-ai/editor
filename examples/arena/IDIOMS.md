# IDIOMS.md — idiomatic engine usage checklist

One page. Distilled from existing doctrine — this project's own `AGENTS.md`
(the "Rules" and "Autoplay bots" sections) and the vgai-engine checkout's
root `AGENTS.md` ("Key Rules"). No rule here is new; this is a checklist
form of what those docs already say.

Legend: **⚙** machine-checked by `npm run check-idioms` (see
`check-idioms.ts`, run without `--strict` = WARN rules don't fail the run;
with `--strict` they do) · **👁** review-only, not machine-checkable.

**The governing principle: the idiomatic path must be the cheapest path.**
If following an idiom below costs more than hand-rolling the alternative,
that friction is an ENGINE defect — report it, don't absorb it. This
checklist exists to catch drift, not to defend drift-causing ergonomics.

| # | Idiom | Why | Self-check |
|---|-------|-----|------------|
| 1 | **World architecture.** The world node IS the entity — no ECS, no mirror layer. On a Three (TSX) root, behavior is an ordinary React component calling `useFrame`: no behavior class, no registry entry, no config schema — props ARE the config. Register a `Behavior` subclass ONLY for a Pixi root, where a data format has to turn a type name into code. Static scenery/lights/UI stay plain objects. | The engine has no separate entity model to drift out of sync with; a `Behavior` on a static prop, or gameplay logic bolted onto a bare `Object3D`, breaks the one-object-one-truth invariant everything else (undo, play-mode adoption, inspector) relies on. A three root has no scene file at all — the TSX source IS the document — so a `Behavior` in a TSX-only game is usually a sign someone ported an older example's shape rather than its intent. | On a TSX root: read the components for `useFrame` bodies and check that state lives in refs, not module scope. On a Pixi root: grep `src/scripts/components/` for classes NOT extending `Behavior` that still do per-frame gameplay work. 👁 |
| 2 | **UI is a React adapter root.** Declare `{"adapter":"dom","entry":"src/ui/...tsx"}` in `vgai.project.json`; the entry default-exports a component. Never call `createRoot`, `hydrateRoot`, `ReactDOM.render`, or mount React from Three.js setup code. Interactive elements set `pointer-events: auto` explicitly. | One manifest root gives the host one lifecycle and makes the UI visible to hierarchy, authoring, HMR, and teardown. A project-created second root bypasses all of them. | `npm run validate-manifest` proves the declaration; the unmanaged-React-root detector rejects alternate mounts. |
| 3 | **State → UI.** Read live game state through `<WorldProvider game>` + `useWorldState(selector)`. No `setInterval`/manual rerender pumps in HUD code. | Polling is the exact pattern the T7.4 state bridge replaced — it's extra code, a frame behind, and reintroduces the "who owns cadence" bug class `useWorldState`'s `frameVersion` gating fixed. | ⚙ (warn, rule **W1**) — `check-idioms.ts` flags `setInterval`/`setTimeout` in a file that also imports `useWorldState`/`WorldProvider`. Scans `src/ui/**` and every manifest dom-root entry/connector regardless of what else the file imports. |
| 4 | **Observability.** A game's surface is its own exported modules: `vgai eval`'s `game.run(({ modules }) => …)` calls its functions directly, and the dev surfaces it writes as TSX contributions read the same modules through `src/tools/use-game-modules.ts`. Events the game emits into the play log are the flight recorder. | If gameplay state is buried in closures nothing exports, agents and the tester have nothing to read or assert on — the game is a black box to every verification surface. | — (structural; no checker polices a shape) |
| 5 | **Verification IS the interactive playtest.** Direct the resident tester from the live session — cheats arrange the situation, `bot.goal` runs behavior, the event log is read on an interval, the run is redirected until satisfied — with varied seeds, goals and dials. Probe ad hoc with `vgai eval`; the play log (`logs/play-*.jsonl`) is the receipt. No spec files, no committed route scripts, no hand-rolled Playwright boots, no `window.__vgai` reached into directly from game code, no `?bot=` query-param plumbing. | Games are fundamentally unpredictable in behavior — a frozen assertion (spec or route alike) enters the endless rewrite cycle. The tester's repertoire grows WITH the game; one transport refuses the same footguns everywhere, and a hand-rolled harness drifts silently and reintroduces the wall-clock-vs-sim-time bugs it solved. | ⚙ (error, rules **E1**–**E4**, **E12**) — playwright imports in game code (Playwright types come type-only from `@vgai/live`), `package.json` scripts invoking `playwright` directly, `window.__vgai` in `src/**`, `?bot=` plumbing in `src/**`, and any automated-test furniture. |
| 6 | **Networking.** Call Colyseus directly — typed `joinOrCreate<T>`, the Callbacks API (`onAdd`/`onChange`/`onRemove`), dynamic-import the SDK so single-player bundles stay clean. Read live schema properties inside `onChange`; never destructure into local copies. **Remote-entity smoothing is `vgai add netcode`, not hand-rolled** — "call Colyseus directly" governs the TRANSPORT; the snapshot buffer and interpolation sampler are project source the capability copies in. | A static top-level import pulls the networking client into every bundle, single-player included; destructured schema fields go stale the instant the server sends the next diff. A hand-rolled interpolation buffer re-derives a ring, a bracket scan and per-axis lerps that already ship — and gets the time base wrong, turning network jitter into visible jitter. | Dynamic-import + Callbacks-API shape: 👁. Static-import drift: ⚙ (warn, rule **W3**) — flags a static top-level Colyseus import in `src/**`. |
| 7 | **Cleanup.** Every `setup()` returns a `dispose()` that removes everything it created — objects, bodies, listeners, UI. | A game that never fully tears down leaks across scene switches and play-mode stop/start cycles; "cleans up" is part of the definition of a working example, not an optional nicety. | Read `dispose()` next to `setup()` and check every object/listener/mount created in `setup()` has a matching teardown line. 👁 |
| 8 | **No wrappers.** Use Three.js/Rapier/library APIs directly — no bespoke abstraction layer standing between game code and the library. | vgai's own precedent (the deleted `net/` wrapper, D2) is that a wrapper without a genuine multi-implementer boundary is a maintenance tax with no payoff; the adapter seam is the one recorded exception. | Look for a module whose only job is re-exporting/thin-wrapping a single library's API with no seam behind it. 👁 |
| 9 | **Trigger identity via components, not display names.** Inside `onTriggerEnter`/`onTriggerExit`, gate on a marker `Behavior` attached to the other entity — never on `other.name === '...'`. | The display name is editable UI state: a rename in the editor's hierarchy panel silently breaks every name-gated trigger, with no error anywhere. Components survive renames. | ⚙ (warn, rule **W4**) — flags `.name ===`/`.name !==` comparisons inside trigger-callback bodies in `src/**`. |
| 10 | **Despawn disposes GPU resources.** A procedurally spawned object that gets despawned must dispose its THREE geometry/material (`geometry.dispose()`, `material.dispose()`) — removing it from the scene graph and physics world is not enough. | THREE keeps GPU buffers alive until `.dispose()` is called; a spawn/despawn loop that only detaches leaks VRAM steadily and fails late, far from the cause. | Read every despawn/removal path for spawned meshes and check for the matching `dispose()` calls. 👁 |
| 11 | **Determinism.** If this project's own `vgai.project.json` declares `determinism.seededRandom: true`, ALL gameplay RNG/wall-clock reads in `src/scripts/**` flow through `ctx.random` (`ctx.random()`/`ctx.random.stream(name)`) — never raw `Math.random()`/`Date.now()`/`performance.now()`. Silent when undeclared — this is an opt-in contract, not a global ban. | A single raw RNG/wall-clock call breaks the seeded-random contract the project claimed: replays, the dev-mode phase trap, and reproducible bug reports all rely on every gameplay draw going through the same seeded stream (D15, `docs/D15-DETERMINISM-DESIGN.md`). | ⚙ (error, rule **E5**) — flags raw `Math.random()`/`Date.now()`/`performance.now()` in `src/scripts/**`, only when `determinism.seededRandom` is declared true. |
| 12 | **Animation owns its phase.** A movement/controller component may expose corrected speed, grounded state, and latched actions, but a separate `animation`-phase `Behavior` owns the XState actor and `bindXStateAnimation` tick. Direct `rig.playClip`/`rig.update` is for isolated previews or simple playback, not gameplay locomotion policy. | Advancing a mixer in `prePhysics` samples state before collision correction and violates the loop's ordering contract. Keeping the animation policy separate also prevents a controller from growing a second, hand-written transition language beside XState. | Clock ordering: ⚙ (warn, rule **W5**) — flags likely humanoid rig/mixer/binding ticks in a non-animation `Behavior`. XState ownership: 👁 — verify gameplay transitions use ordinary XState and missing required clips fail during initialization. |
| 13 | **Await required component setup.** `Behavior.init()` may return a Promise; make it `async` and await required models, clips, maps, or other initialization. Detach only work that is genuinely optional. | The component manager deliberately withholds updates and Play’s setup acknowledgment until async initialization settles. `void this.loadClips()` bypasses that guarantee and turns a startup failure into a late unhandled rejection. | ⚙ (warn, rule **W6**) — flags load-like `void this.load…()` calls inside `init()`. |
| 15 | **The tester's repertoire stays current with the game.** New mechanics get behaviors in `src/bot/behaviors.ts` in the slice that ships them — the repertoire growing WITH the game is how playtest coverage grows. | A stale repertoire silently stops covering the game: live playtests keep 'passing' while exercising less and less. | 👁 — review `src/bot/behaviors.ts` against the mechanics shipped since it last changed. |
| 16 | **Authorable R3F stays ordinary R3F.** A reusable spatial component accepts the matching `ThreeElements['group']`/`ThreeElements['mesh']` props and forwards them to exactly one outer native object. Give every instance a meaningful `name`. The outer root owns authored placement; animation, recoil, bobbing, and model-axis correction happen on inner children. Components can live in normal shared modules and travel through relative imports, aliases, and re-exports; no registration or vgai prop type is needed. Fragments remain valid non-spatial containers. | The editor can safely add and persist a missing callsite transform only when source proves where that prop lands. Mutating the authored root from `useFrame` creates the familiar drag-then-snap-back conflict. Standard R3F props keep the code recognizable to people, tools, and coding models without an Actor wrapper or proprietary scene DSL. | Source-proven by the project-local R3F authoring index. Validate-on-save reports `R3F002` for incomplete native transform forwarding, `R3F003` for multiple spatial roots, `R3F004` for unnamed spatial instances, and `R3F005` for runtime motion applied to the authored outer root; the editor still runs valid R3F and disables only unsafe channels. Two carve-outs, derived from your own source: a SIMULATION-OWNED root (no transform props accepted or spread, and the component drives its root ref every frame in `useFrame` — prey, projectiles) is exempt from `R3F002`/`R3F005`, and the editor refuses transform edits on it with a reason naming simulation ownership; a KEYED `.map()` instance is exempt from `R3F004` (derive a per-item name like `` name={`rabbit-${i}`} `` when you want hierarchy labels). |
| 17 | **Never a positive `useFrame` priority unless you render.** Behavior components order themselves with `0`/negative priorities; a positive priority tells react-three-fiber you are TAKING OVER rendering, so fiber skips its own render and the world goes BLANK while every hook and state read stays healthy. | The failure is invisible to every non-pixel check — a probe build shipped a world reporting perfect health (`game.state` ticking, no errors, no mount failures) with an empty canvas, and the cause was priorities `2`/`3` chosen to mean "after physics". | ⚙ (warn, rule **W8**) — flags a positive numeric `useFrame` priority in `src/**` unless that callback itself calls `.render(` (genuinely taking over). `idioms-ignore W8 <reason>` is the escape. |
| 18 | **Play each slice before writing the next.** Enter Play and LOOK at the game between gameplay slices — `npm run vgai -- play` plus a live playtest answers the question; re-reading the code does not. | A game written blind fails in ways typecheck cannot see: a blank canvas, an invisible mesh, a camera inside the geometry. In the probe build that motivated the rule, 60% of the session (59 minutes, 187 tool calls) went by before the first pixel, and 4 of that build's 5 worst bugs were pixel-only — every one of them found only afterwards. | ⚙ (warn, rule **W9**) — flags 5+ commits touching gameplay source since the `.vgai/scaffold-baseline.json` scaffold anchor with no `logs/play-*.jsonl` receipt on disk. The receipt is written by the editor server itself, so the warning clears by playing the game and never by intending to. Silent without git history or a committed baseline. |
| 19 | **A DEVLOG'd live playtest is the handoff proof.** The play log receipt plus reviewed media in `media/` and the DEVLOG entry that judges them — behaviors merely existing is not evidence. | Blind probes built verification artifacts to satisfy existence gates and never ran them — 'THE proof' fired zero times across 150+ combined turns while the reports claimed verification. A receipt written by the tool itself cannot be produced by intending to play. | ⚙ (warn, rule **W9**) plus 👁 — the DEVLOG entry's media and outcome are review subjects. |
| 20 | **Every shipped 3D asset meets the floor: a NAMED prefab component, a colocated CSF story, named nodes.** The unit is the asset — the thing a designer selects, places or duplicates as one piece — living in `src/prefabs/<Name>.tsx` with `<Name>.stories.tsx` beside it and zero authoring warnings at handoff. (`.agents/skills/vgai-3d-assets/SKILL.md`, "The REQUIRED floor".) | Without the story the asset is invisible to the editor's Content tab — the story IS the registration — and without names its parts are un-addressable in the hierarchy the product exists to sell. Two blind probes shipped authoring warnings knowingly as "later polish"; one shipped a single monolith with 76 anonymous mesh callsites and no prefab decomposition. Both handed off with every other gate green. | ⚙ (rules **E9**, **E10**) — WARN with a standing count the operator reads (the committed-route ship gate is retired; handoff judgment is the DEVLOG'd playtest). E9 runs the editor's own R3F analyzer offline through this project's `@editor/*` tsconfig mapping — no running editor needed — and reports each `R3F00x` at its callsite; E10 flags a `src/prefabs/**` module with no colocated story naming it as `meta.component`; its escape for a non-placeable (a sky, an atmosphere, dev scenery) is RECLASSIFICATION — move it to `src/components/` — never a hollow story, which registers noise into the Content palette. |

| 21 | **No automated tests in a game project.** No `*.test.*`/`*.spec.*` files, no test-runner dependency, no test script, no committed route scripts. The playtest is INTERACTIVE: cheats set the situation, bot behavior runs, the event log is read on an interval, the run is redirected live — until satisfied. The play log is the receipt. | Games are fundamentally unpredictable in behavior, so a pre-written assertion file enters an endless cycle of rewriting assertions and actions (owner ruling 2026-08-21, measured live: three assertion renegotiations in twenty minutes on one balance suite). | ⚙ (error, rule **E12**) — flags test files anywhere, test-runner deps, and scripts invoking one. |

## Running it

```bash
npm run check-idioms          # WARN rules print but don't fail the run
npm run check-idioms -- --strict   # WARN rules also fail (exit 1)
```

Findings print `file:line`, the rule id + idiom name, a one-line "why", and
a one-line fix pointer. A false positive on a heuristic (WARN) rule can be
suppressed on the flagged line with a comment giving a REQUIRED reason —
an empty reason does not suppress:

```ts
setInterval(pollLegacyThing, 250); // idioms-ignore W1 legacy bridge to a 3rd-party SDK callback, not app state
```

See `check-idioms.ts`'s header comment for the exact rule list and the
scanner's known limitations (it's a line/regex scanner, not an AST pass).
